# 去掉你的PDF审校执念吧！

接触过不少出版社的编辑，发现有一部分人想使用审校软件提高效率，却有很重的PDF执念：总想着直接把PDF丢进去一键审校，不用来回转换文件，也不用跟作者要源文档。看起来省事，实际是给自己挖坑。
现实是PDF版本过审校软件，目前没有一个软件能彻底解决。
PDF本质上是“画面描述文件”，它保存的是文字摆在哪里、长什么样，而不是一篇结构完整、顺序清晰的文稿。分栏、图文混排、公式、异形排版、书眉页码、脚注尾注混在一起，文本流很容易错乱。如果是扫描版PDF，还要先靠OCR把图像重新识别成文字；就算是文字可以复制的PDF，提取出来的文本也经常断行乱序、标点错位、空格乱飞。形近字、异体字、繁简转换、竖排文字、模糊网点、水印底纹，任何一处识别偏差，都可能顺着管道进入审校环节。
OCR导致的文本质量不高，误报、漏报长期存在。而且最麻烦的误报、漏报，往往不是审校规则判断错了，而是软件拿到的“稿子”本身已经变了样。
很多审校工具的规则库，是针对干净、连续的正文文本设计的。一旦原始文本被OCR或者PDF提取环节污染，后果很直观：明明没有差错，软件频繁误报；真正的错别字、用词错误、数字规范问题，反倒藏在错乱的文本里被漏掉了。编辑还要花大量时间，甄别哪些报错是PDF解析带来的垃圾信息。本想靠审校减负，结果变成二次返工。
更要紧的是，出版质量责任不能跟着文件格式一起“转交”出去。审校软件可以辅助检查字词、语法、知识、规范和逻辑，却替代不了三审三校，也替代不了编辑对稿件的整体把握。如果底本在转换中已经悄悄走样，后面查得再细，也可能是在一份“失真的稿子”上精益求精。
这里不是说PDF完全不能用。PDF适合终稿比对、样稿查阅、出样归档，也适合检查图片错位、线框、字号、出血等版式问题。说到底，它更适合用来“看版”，不适合直接拿来“审文字”。
文字审校的最优链路，永远是优先拿源文件，比如Word、Markdown、XML这类保留完整正文结构的文稿。源文档文本连续、段落清晰、语义完整，审校规则才能稳定落地，误报、漏报也会明显减少。编辑加工、作者修改、排版前检查，这些环节的文本相对干净，修改还能直接落实到稿件中，不必在PDF和原稿之间来回誊抄，工具的价值才能真正发挥出来。
很多编辑的PDF执念，根源其实是习惯：交付印刷厂的是PDF，外审返回的是PDF，久而久之便觉得，PDF是定稿，就该拿它来审。
但要分清两件事：定稿版式是PDF的事，文字差错校验主要是源文件的事。版式层面的差错，交给版式校对工具或者人工看样；文字、标点、数字、史实、专有名词、语法等差错，尽量在源文本阶段完成审校。排版之后，再把PDF作为版式清样使用，核查页码、目录、图表位置、标题层级和跨页断行，必要时辅以软件复验，但不要把它当成唯一的审校入口。
当然，现实工作中总会遇到只有PDF、拿不到源文件的情况。这种时候，PDF加OCR审校只能作为退而求其次的备选方案，而且要提前降低预期：优先使用可复制文字的版本，尽量少用扫描件；扫描件必须先识别、再抽查底本，重点核对数字、专名、引文、注释和参考文献；遇到古籍、科技书、辞书和复杂多栏版式，更要谨慎。软件报出来的，要回到原版面确认；软件没报出来的，也不能默认没有问题。机器结果只能当线索，不能直接采信，更不能当结论。
所以，去掉PDF执念，不是不要PDF，更不是否定技术，而是让每种格式回到它该在的位置：源稿负责内容审校，PDF负责版式确认，软件负责放大人的眼力，人负责最后的判断。
别再执着于“PDF一键审校”了。选对文件链路，才是用好审校工具的第一步。
编辑真正该执着的，从来不是“把什么文件丢进软件”，而是书稿出去之后，经得起读者一页一页地看。
