很多知识创作者已经能写出结构完整的稿子，却仍然卡在同一个地方：怎样把抽象概念变成观众愿意继续看下去的画面？
真人出镜需要镜头表现力，混剪需要素材版权，模板化剪辑又容易让所有内容长成同一种样子。近两年的生成式视频提供了新的可能，但它也有明显边界：人物会漂移，文字经常失控，数据图表很难精确复现，同一个镜头重做几次，结果可能完全不同。
开源项目
**BB-Video**
选择了一条不同的路。
它不是一个新的文生视频大模型，也不是网页版剪辑器，而是一套面向 Agent 的视频制作 Skill。项目用 HTML、SVG 和 Canvas 绘制每一帧，用无界面 Chrome 逐帧渲染，用代码合成音乐和音效，最后交给 ffmpeg 编码成 MP4。在当前的 30 种风格版本中，用户只需要选择一种视觉语言，旁白、分镜、配音、排版、动效和检查由 Agent 继续完成。
项目地址：https://github.com/BubbleBrainBB/BB-Video

**01**
POSITION
#### 它不是“文生视频”，而是“代码动画生产线”
理解 BB-Video，最重要的是先把概念分清。
常见的 AI 视频工具，大多根据提示词直接生成像素。BB-Video 不预测下一帧，也不依靠素材库拼接。它把视频拆成一组可以检查、可以复用的代码对象：
文字由 DOM 排版；
图形由 SVG / Canvas 绘制；
产品界面使用真实截图；
每个动画由时间参数 t 驱动；
配音、字幕、音乐和音效共享同一条时间轴；
最终画面由 Chrome 逐帧截图，再由 ffmpeg 编码。
项目最关键的设计，是让每一帧都成为时间的纯函数，也就是 renderFrame(t)。
这句话听起来偏工程，但对实际创作很重要：给定同一个项目，不管渲染多少次，任意时间点的画面都是一致的。制作者可以先检查第 6.2 秒的字幕有没有压住图表，也可以只渲染几个关键帧确认构图，再决定要不要生成整支视频。
它带来的是三种稳定性。
**第一，可编辑。**
画面里的一句文案、一条曲线、一个产品按钮，背后都有明确的对象和参数，不需要从一整段生成视频里“碰运气”重抽。
**第二，可检查。**
文字是否出画、内容是否提前出现、转场是否闪帧、配乐里是否有过长的空拍，都能变成规则和报告，而不是完全依赖人的肉眼。
**第三，可复用。**
一套风格模板能够服务不同主题。白板可以讲物理，也可以讲商业；日漫可以讲咖啡因，也可以讲产品流程。风格负责视觉语法，内容仍然由当前选题决定。
BB-Video 同时支持两大类视频：
**讲解视频**：有旁白、字幕和垫底音乐，适合科普、历史、概念、解题、教程、新闻和数据；
**宣传视频**：没有旁白或减少旁白，按照节拍组织文字、界面和音效，适合网站、App、软件和产品发布。
两种工作流共用一套渲染与声音核心，也都支持 16:9 横屏和 9:16 竖屏。对知识创作者来说，它真正提供的不是“一个视频模板”，而是一套从文字内容到动态视觉的转换机制。

**02**
STYLE SYSTEM
#### 30 种风格，不是 30 个滤镜
市面上很多“风格预设”只改变颜色和字体。BB-Video 的每一种风格，实际上都包含一整套视觉语法：
画面材质；
字体和排版规则；
镜头运动；
转场方式；
图形组件；
声音气质；
适合的内容类型。
同样是“为什么天空是蓝色”，白板会把它拆成光的散射和推导过程，折纸会把纸面折叠成光路，波普会把它变成漫画格，字符画则会让整个解释从字符噪声中显影。
所以，30 种风格真正提供的，是 30 种把复杂内容转成画面结构的办法。它们共同覆盖了解释、叙事、产品演示、证据整理、空间系统与情绪传播，而不是简单地把同一套动画换 30 种配色。

这组风格解决的主要不是“好不好看”，而是“观众能不能沿着画面理解逻辑”。白板适合展示推理过程，包豪斯与瑞士排版适合把信息和数字压成明确秩序，ASCII 与欧普适合表现系统和精确性，蓝图让“机构怎么动”成为可见证据，颗粒插画与绘本则把过程放进更温和、更容易接近的叙事里。

**2. 让知识与文化进入叙事：水墨、皮影与刺绣长卷**
| **风格** | **视觉特征** | **更适合的内容** |
| ink 水墨 | 一幅持续移动的手卷，笔触、印章、国画人物和留白共同构成镜头 | 古诗词、典故、中国历史、思想、文化、自然与季节 |
| shadow 皮影戏 | 灯照幕布、刻花牛皮人物、关节点和操作杆，场景切换依靠灯光明暗 | 有角色、有冲突的历史故事，民俗文化，创始人故事和传奇叙事 |
| tapestry 贝叶挂毯 | 亚麻布、羊毛刺绣、茎绣轮廓、鸟兽花边和中世纪侧身人物，图案会一针一线绣出来 | 文明史、技术史、城市史、工艺沿革，以及“故事发展到现在”的编年叙事 |
这三类风格的重要性，不只是“复古”或“中国风”。它们把叙事的时间关系放进了画面本身：水墨依靠长卷的横向推进，观众是在浏览一段连续的文化空间；皮影戏依靠幕布、灯光和角色动作，观众是在看一场被压缩的戏剧；挂毯则用卷轴、连续人物和刺绣过程表达历史的沉积。
如果用白板解释一首诗，重点会落在字句、意象和结构；如果用水墨，画面本身就是诗的一部分；如果用挂毯讲一项技术如何跨越时代，工艺和时间会同时成为叙事材料。风格选对了，视觉会承担解释，而不是只替文字配图。
水墨风格样片，唐诗《登鹳雀楼》
这类风格不是静态国风背景，而是包含书写、景别推进和长卷转场。

| manga 日漫 | 黑白网点、漫画分格、速度线、拟声词、翻页和震屏 | 把科学或概念变成对决，带反转的故事，面向年轻观众的产品叙事 |
| pixel 像素 | 8-bit 像素小人、游戏菜单、血条、关卡和芯片音乐 | 游戏、编程、AI 产品、分步流程、儿童科普和游戏历史 |
| lumen 暗调励志短片 | 近乎全黑的房间、单一动机光、巨大投影、慢推镜头、第二人称旁白与封面式字卡 | 作息、拖延、专注、运动、倦怠等自我改善主题，以及健康与专注类产品 |
| parable 3D 火柴人寓言 | 黑色虚空、镜面地面、白色火柴人、一个红色意义物件和固定远景 | 15 至 45 秒的单观点表达、复利、行动与等待、习惯与长期主义，竖屏优先 |
这些风格的共同点，是让观众进入一个已经熟悉的媒介，或者迅速接受一条清晰的叙事规则。
聊天记录把信息关系变成人与人之间的往来。谁先说话，谁引用了一条资料，谁正在输入，本身就构成叙事节奏。日漫把抽象冲突转成视觉冲突：咖啡因与受体的作用，可以变成一场少年漫战斗；一个流程中的瓶颈，也可以变成关卡中的敌人。像素游戏则天然适合“选择—反馈—结果”的结构。
暗调励志短片把光线、影子和镜头停留变成情绪控制。它不依赖夸张转场，而是让观众在近乎黑暗的空间里跟随一个角色，把“道理”转化为一个正在发生的夜晚。火柴人寓言则更克制：两个角色对同一件事采取相反做法，红色物件承载意义，观众通过行动差异自己得出结论。
它们体现了一个很重要的知识视频原则：**解释并不一定要长得像课堂。媒介越具体，情绪入口越清楚，抽象关系有时反而越好懂。**
聊天记录风格样片《一骑红尘妃子笑》
让读者快速理解“聊天界面不是一张整屏截图，而是可以组织叙事、引用和转场的结构”。
**4. 把产品卖点变成动作：发布会与玩具三维**
| **风格** | **视觉特征** | **更适合的内容** |
| launch 发布会动效 | 品牌色舞台、大字卡点、真实产品界面、推镜、甩镜和闪光 | SaaS、AI 工具、软件功能和产品发布 |
| toy3d 玩具三维 | 真实界面变成桌面上的实体屏板，软胶玩具在界面中点击、拖动和跳跃 | 有完整 UI、强调交互流程的产品，以及需要具象演示的抽象机制 |
发布会风格的优势在于节奏。它会把产品页里的标题、数字、截图和功能动作重新编排到音乐节拍上。真正关键的不是“大屏特效”，而是让用户注意力依次落在“产品是什么、解决什么、怎么用、结果是什么”。
玩具三维则进一步把 UI 变成可操作的空间。点击是玩具落在按钮上，拖动是玩具抱起组件，输入是玩具在键盘上跳。它适合解释编辑器、看板、IDE、设计工具这类“只看静态截图很难感受到交互”的产品。
**5. 用证据组织观点：剪报、纸艺拼贴、老新闻片、录像分析和悬疑**
| **风格** | **视觉特征** | **更适合的内容** |

| collage 纸艺拼贴新闻解说 | 撕边纸片、网点照片、红色印章、打字机引语、图钉时间线与纸上图表 | 带历史背景的新闻解释、债务与价格、政策变迁、档案照片和长期趋势 |
| newsreel 老新闻片 | 三十年代影院新闻片、档案照片、字幕卡、橡皮章、胶片划痕和铜管乐 | 新闻回看、历史事件、记录核验，以及有真实照片的复古产品故事 |
| filmroom 录像分析 | 真实录像定格、画笔圈人、跑位线、慢放回放、战术板和数据图 | 体育拆解、带空间位置的操作演示、屏幕录像讲解 |
| mystery 悬疑探秘 | 4:3 老电视、假正经科普、编号“症状”、卡通贴纸和证据墙 | 习惯观察、辟谣、误区、日常谜题，以及带娱乐性的产品叙事 |
对于新闻、财经与知识解释，难点往往不是把观点说得更响，而是让证据可见。
剪报风格会把真实文件变成镜头里的证据，镜头可以从整页推进到被引用的那一行；纸艺拼贴让新闻纸、老照片、时间线和图表像调查材料一样铺在同一张桌面上；老新闻片用来源标签、档案照片和字幕卡建立时代感；录像分析直接停在某一帧，把动作、路线和空间关系画出来；悬疑风格则适合把“常见误区”当作待破解的问题，用证据墙和排除法建立推理过程。
这些风格适合的不是“替用户编结论”，而是把已有的出处、数字、画面和因果关系组织得更清楚。
**6. 空间、系统与电影感：等距世界、地图和预告片**
| **风格** | **视觉特征** | **更适合的内容** |
| isometric 等距微缩世界 | 45 度俯视、带底座的地块、低多边形建筑、传送带、货车和路线 | 物流、供应链、支付、互联网、城市系统，以及“跟着一个对象走完全程” |
| map 地图动画 | 用真实地理数据绘制地图，路线逐笔画出，镜头可从地球推进到街道并跟随交通工具 | 交通、城市、贸易、迁徙、历史路线、事件扩散和地理位置解释 |
| trailer 电影预告片 | 2.39:1 遮幅、类型化电影镜头、青橙调色、颗粒、字卡、BRAAM 和定档页 | 虚构影视、书籍、游戏，以及“世界改变之前与之后”的产品叙事 |
等距微缩世界与地图动画解决的是“观众不知道自己在系统哪个位置”的问题。一个包裹从仓库到用户家门口，用流程图只能说明顺序，用等距世界则能同时展示空间关系、参与者、时间成本和路径变化。地图则把真实地理数据变成镜头运动，适合解释“在哪里、怎样连接、先后经过哪里”。
电影预告片是另一种极端：它不负责完整解释，而负责在几十秒内建立情绪、冲突和记忆点。把产品发布写成预告片，重点不是虚构大片感，而是把“旧世界—转折—新结果—名称与时间”的叙事压进一套高强度节奏。
地图风格样片《波士顿地铁》
能同时展示真实地理数据、线路生成、镜头从宏观到微观的推进，以及知识内容的证据感。
电影预告片风格样片《深空回声》
它展示了代码动画能达到的视听强度，也适合作为全文从“知识解释”转向“情绪传播”的视觉高潮。
**03**
WORKFLOW
#### 从一段话到成片，Agent 到底做了什么
BB-Video 最容易被误解成“输入一句话，直接输出视频”。实际上，它更像一条可审查的生产流程。
**讲解视频：先确认事实，再决定画面**
讲解视频的官方流程可以概括为六步。
**第一步，整理事实。**
Agent 先把需要讲清的核心观点、数字、出处和不能出现的错误写进 brief.md。所有最终出现在画面里的文字，都要能够在这里找到依据。
**第二步，写旁白和分镜。**
每一句旁白都要对应一个真正承担信息任务的画面：一张图、一组对比、一条公式、一段流程、一张标注过的截图。单纯放大一个关键词不算“视觉解释”。
**第三步，生成配音和时间轴。**
项目使用 edge-tts 生成旁白，同时得到逐词时间。之后画面出现和消失的时间，都以这份时间轴为准，而不是靠手工猜秒数。
**第四步，按镜头绘制动画。**
Agent 根据选定的风格，用代码绘制画面和运动。复杂镜头可以先输出关键帧截图，确认构图后再继续。
**第五步，执行三类检查。**
第一类是 lint，检查文字重叠、出画、字幕遮挡、未读完就消失、只有文字没有信息图等问题；第二类是静态总览，逐句检查旁白结束时的画面；第三类是连续帧检查，专门观察转场、擦除、镜头运动和角色动作。
**第六步，正式渲染。**
最终输出 1080p、30fps 的 MP4，并自动生成封面、字幕文件和适合分享的全貌图。白板与孔版印刷风格还能输出整张“知识地图”或版式总览。
这套流程真正的价值，在于它把“视频好不好”拆成了可以被逐项验证的问题。
**宣传视频：先读产品，再卡住节拍**
宣传片工作流更接近导演而不是编辑。
用户提供一个网址后，Agent 会以只读方式打开页面，整理产品文案、关键数字和品牌颜色，采集合法的真实界面截图，再决定主要用 UI 演示、文字卡、数据图还是对话来建立叙事。
随后，视频按照音乐节拍组织画面。默认参考 120 BPM，一个节拍约为 0.5 秒，一段通常为 2 秒。文字出现、界面切换、点击动作、转场和音效都要落到音乐上。项目还会检查连续 1 秒以上的“空放”：画面上没有新信息，音乐也撑不起注意力的时间段。
横屏与竖屏并不是简单裁切。对于 9:16，浏览器窗口会换成手机框，卡片和图表重新纵向排列，标题和关键信息需要更大的字号。Agent 还要分别检查两种比例下的出画、遮挡和标题裁切。
**04**
ENGINEERING
#### 真正的工程亮点：不是画面，而是可控性
BB-Video 的很多优势看起来属于美术，实际上来自工程约束。
**1. 时间必须来自统一时钟**
GSAP、Three.js、Matter.js 等动画库可以使用，但它们不能自己按真实时间运行。所有动画都要被定位到同一个时间参数 t。这样，暂停、拖拽、跳帧与逐帧渲染得到的是同一个状态。
**2. 画面信息必须可追溯**
系统会检查画面上的文字是否来自事实清单。数字、引语、产品定价、功能名称如果不在 brief.md 里，就会触发提醒。它不能替代人工核查，但能减少“动画做得太顺，错误文案就这么上线了”的情况。
**3. 声音由同一套工程生成**
音乐和音效可以直接由代码合成，也能使用制作者提供的音频。旁白、音乐和音效会统一混合；音乐在说话时自动压低，最终目标响度约为 -16 LUFS。对没有音频团队的独立创作者，这减少了大量重复处理。
**4. 成片之前就能检查成片问题**
系统会识别文字跳动、单帧闪烁、空放、元素重叠、文字过小、裁切和错误的时间交接。对于竖屏，还会额外检查平台顶部和底部安全区。渲染之后，还会对成片做跳帧、闪帧和静默段检查。
**5. 输出不只是 MP4**
一次完整项目可以同时得到：
视频文件；
可拖动预览的网页；
封面；
字幕文件；
白板或印刷版式的全貌图；
第三方素材的来源与许可清单。
这让视频不再是一次性交付物，而是可以继续修改、切条和复用的内容资产。
蓝图工程图样片《机械表里发生了什么》
它最直观地说明“代码动画不等于随意变形”：齿轮按齿数和传动关系啮合，擒纵机构锁止与释放，尺寸、引线、剖面和零件表共同构成一份会动的工程图。这是技术型知识视频很有代表性的能力。
**05**
SELECTION
#### 30 种风格怎么选：从内容关系出发
选择风格时，不建议先问“哪个最酷”，而应该判断内容中最重要的是什么关系。
| **内容关系** | **优先考虑** |
| 需要展示推导、公式和逐步拆解 | whiteboard |
| 需要栏目感、比较、数字和文档化表达 | riso、dossier |
| 需要榜单、基准、价格和严格的信息层级 | swiss |
| 需要文化语境、诗意或历史氛围 | ink、shadow、tapestry |
| 需要角色、冲突和戏剧节奏 | shadow、manga、trailer |
| 需要自我改善、习惯和情绪推动 | lumen、parable |
| 需要解释人与人之间的信息关系 | chat |
| 需要解释系统如何运转、对象经过哪些环节 | isometric、map、filmroom |
| 需要展示机械结构、工程关系和规格 | blueprint |
| 需要展示真实产品和交互流程 | launch、toy3d |
| 需要把抽象观点变成鲜明图形 | bauhaus、op、pop、cutout、ascii、grain |
| 面向儿童、游戏用户或流程选择 | pixel、chat、storybook |
| 需要温和、手工、可触摸的质感 | origami、cutout、tapestry |
一个简单的判断方法，是看内容里最强的证据是哪一种：
最强证据是推理过程，用白板；
最强证据是人物行动，用水墨、皮影、日漫或绘本；
最强证据是机制与结构，用蓝图工程图；
最强证据是真实界面，用发布会或玩具三维；
最强证据是文件与出处，用剪报、纸艺拼贴或老新闻片；
最强证据是地理与路线，用地图；
最强证据是系统路径，用等距世界；
最强证据是数字与秩序，用瑞士动态排版；
最强证据是氛围和转折，用预告片、暗调短片或火柴人寓言。
如果暂时不确定，最稳妥的起点是白板。它允许公式、图示、文字、角色和镜头移动共存，最适合验证“内容是否真的被画面解释了”。

**07**
FIT
#### 它适合谁，又不适合谁
BB-Video 很适合以下场景：
知识博主需要稳定产出概念解释、历史和新闻视频；
开源项目需要不依赖实拍素材的产品介绍；
软件团队需要把功能流程、架构和数据讲清楚；
教育团队需要可修改、可复用、可批量本地化的课程视频；
内容团队需要同时输出横屏视频、竖屏视频、封面与字幕。
但它并不适合所有视频。
如果你的核心内容依赖真实人物表演、纪录片采访、复杂实拍调度，BB-Video 不能替代摄影和剪辑。如果你需要根据一句提示生成电影级人物镜头，它也不是扩散视频模型。对于需要大量真实运动素材、版权音乐和多人协作的长视频项目，传统视频生产流程仍然更合适。
更准确地说，它擅长的是：**把结构化知识、界面流程和品牌信息，转换成由图形、文字、运动和声音组成的解释系统。**
**08**
SAFETY
#### 开源之外，还需要看清隐私与安全边界
BB-Video 使用 MIT 许可证，代码可以修改、复用和分发。但第三方组件仍遵循各自许可证，包括 KaTeX、Three.js、GSAP、Matter.js 以及使用的字体。
使用前需要注意几项边界：
旁白文字会发送给 Microsoft 的在线语音服务，不应把机密内容直接写进配音；
制作产品宣传片时，无界面 Chrome 会打开用户提供的网站并截图，不会登录或下载站点文件；
搜索档案照片时，搜索词会发送给 Wikimedia Commons API，下载前应确认许可和署名；
渲染器会打开项目中的 index.html，这意味着会执行项目代码，只应渲染自己或可信 Agent 生成的项目；
项目没有遥测、账号或 API Key 要求，但 CDN、字体和语音服务仍然需要网络。
这些并不是劝退，而是专业使用任何 Agent 工具前都应该掌握的基本边界。
**09**
SYSTEM
#### 从“生成一段视频”到“建立视觉生产系统”
BB-Video 最值得关注的地方，不是把风格做成了 30 个按钮，而是把每一种视觉语言都变成了可执行的创作约束。
过去，知识创作者常常在“统一视觉”和“每个选题都需要不同表达”之间来回摇摆。统一模板会让账号显得稳定，却牺牲内容适配；每次重新设计又无法形成可积累的方法。
BB-Video 给出的答案是：把视觉语言做成一组可复用的系统，再让 Agent 根据主题选择其中一种。
白板保存推理过程，地图保存空间关系，聊天记录保存信息往来，剪报与拼贴保存证据来源，蓝图保存工程关系，皮影保存角色与冲突。它们不是不同的皮肤，而是不同的认知入口。
这也是知识视频真正稀缺的能力：不是把一段文字念得更快，也不是每隔三秒塞一个转场，而是让画面承担一部分思考，让观众看见概念之间的结构。
如果 2023 年的 AI 视频关键词是“生成”，那么下一阶段更值得关注的关键词，可能是“组织”。
组织事实，组织镜头，组织声音，组织证据，也组织一种能够被反复使用、持续修改的视觉语言。
BB-Video 正是在这个方向上，提供了一个足够具体、足够开放，也足够值得拆解的开源样本。
3D 火柴人寓言《复利》
它用无旁白、单观点、强对比的方式说明 BB-Video 也能做短而克制的表达。
手绘绘本吉祥物样片《感冒了，身体怎么打败病毒》
适合强化“复杂过程也可以被讲得友好”这一判断，覆盖儿童、家庭与原创角色场景。
纸艺拼贴新闻解说《黄金：从 35 美元到 5318 美元》
如果文章希望强化“新闻证据链”，这支样片能展示档案照片、时间线、纸艺图表和年代叙事如何被组织在同一张桌面上。文件较大，适合作为重点章节的加分项。
**∞**
EPILOGUE
#### 结语
如果你的下一个选题正卡在“文字已经写清楚了，但不知道该怎么变成画面”，不妨先用 BB-Video 做一个最小实验：只做一个概念、一条证据、一张结构图，用 60 秒把它讲清楚。
你会很快发现，决定视频质量的仍然不是模型参数，而是三个问题：
你希望观众记住什么？
哪一个画面能证明它？
哪一种视觉语言最适合这段关系？
把这三件事想清楚之后，Agent 才真正有了可以执行的创作方向。
