## 输入一个字，看它三千年的样子：这个开源项目把甲骨文到简体排成了一条时间轴
> 💡 **输入任意一个汉字，它就把这个字从商代甲骨文、到小篆、到繁体、再到简体的三千年，排成一条时间轴给你看。读音带中古音和上古音构拟，释义直接引《说文解字》原文，同声符的字族还能点着往下追。10,249 个小篆、1,425 个甲骨文、9,815 条《说文》释义，查不到的一律显示横杠——不编数据。
**
![](assets/403feb00ed7281e8-1.jpg)
**先说一个挺戳人的念头：我们每天写的中文，每个字其实都有几千年的身世。**
**但你几乎从没机会"看一眼"它的来历。**⁠ 甲骨文长什么样、小篆怎么写的、《说文解字》当年是怎么解释的——⁠**这些知识散在一堆厚厚的学术书里，普通人根本翻不到。**
**结果有人把这件事，做成了一个网页：输入一个字，一页看完它的形、音、义、族。**
**这个项目叫 **⁠**一个字的一生（yigezi）**⁠**，作者是 GitHub 上的 Ivan666jjj。**⁠ 更准确地说，⁠**这是"一位学汉语言文学的朋友和她舍友聊出来的点子"。**
**打开就能用，不注册、不收费。**
![](assets/403feb00ed7281e8-2.png)
#### 它做了什么：把"一个字"拆成四个维度
**这是它最聪明的地方——它不是做了个花哨的动画，而是把每个汉字，用四个专业维度完整地"解剖"开。**
| **维度** | **内容** |
| **形** | 甲骨文 → 小篆 → 繁体 → 简体，四体时间轴，从商代一路到今天，**带年代标注** |
| **音** | 现代拼音 · **中古音**反切与音韵地位 · **上古音**构拟 |
| **义** | **《说文解字》原文** • 反切 + 部首 + 卷次 + 重文 |
| **族** | **谐声系列**（同声符字族，可点击跳转接着看） |
> **你描述的每一个细节都对：四体时间轴、中古/上古音、引《说文》原文、同声符字族可点——它确实做到了。
> **
**更细的一点是，它还带了"古文字纠正"：部分字会给出「《说文》说 ××，甲骨文实为 ××」的对照。**⁠ 什么意思？下面说。
#### 它收录的数据，多到什么程度
**官方 README 里列得清清楚楚，全是硬指标：**
| **项目** | **数量** |
| **小篆字形** | **10,249** |
| **甲骨文字形** | **1,425** |
| **《说文》释义** | **9,815** |
| **谐声系列** | **740** 组 |
| **中古音** | **7,964** |
| **上古音构拟** | **3,163** |
> **你说的"10249 个小篆、1425 个甲骨文、9815 条《说文》释义，查不到的一律显示横杠，不编数据"——一字不差，全都对得上。
> **
**这句话里，最打动我的是最后半句："查不到的一律显示横杠，不编数据。"**
**在一个 AI 张口就编的年代，一个查字工具敢说"没查到就留白"，是需要定力的。**
#### 三种配色 + 导出，细节很讲究
**它不是只把数据堆给你，用起来也很舒服：**
- **三种配色**⁠：⁠**宣纸**⁠（温润米黄）、⁠**碑拓**⁠（黑底白字，像拓片）、⁠**藏经**⁠（古卷质感）——⁠**你提到的那三种，它全有。**
- **导出**⁠：⁠**单字能导出 JPG 图片**⁠，⁠**演变过程能导出 GIF 动图**⁠（内含作者自研的 GIF89a 编码器，因为浏览器原生不支持 GIF 编码），⁠**还支持批量导出。**
- **#z=字 参数**⁠：⁠index.html#z=江⁠ 直接打开某个字，⁠**方便分享。**
- **单页应用，离线可用**⁠：字体按需子集内嵌，下载 ⁠index.html⁠ + 两个字体文件放一起，⁠**双击就能用，不联网。**
**宣纸、碑拓、藏经那三种配色，配上甲骨文和小篆的字形，随便截一张图都是壁纸级的。**
#### 技术上的巧思，藏得很深
**别看它是个"查字"页面，里面的工程量不小。**
- **单页 HTML + 内联数据，无框架、无依赖**⁠——纯 HTML，⁠**不引入任何前端框架。**
- **字体按需子集**⁠：完整字体 ⁠**25.8 MB，用 pyftsubset 压成 8.5 MB 的 woff2**⁠，才能塞进网页里秒开。
- **自写 GIF89a 编码器**⁠（固定调色板 + LZW 算法）——⁠**因为浏览器原生不能生成 GIF，作者干脆自己写了一个。**
- **演变动画、导出功能，全部用 Canvas 实现。**
**一个语言文学背景的人，能把字体子集化、GIF 编码这些活儿都干了，是真下了功夫。**
#### 数据从哪来：全是正规学术来源
**这一点特别值得说——它的数据，没有一条是"随手找的"。**
| **数据** | **来源** | **授权** |
| **小篆字形** | 开元小篆 + 全字库说文解字 | OFL-1.1 / OGDL |
| **甲骨文字形** | Oracular 鏡原甲骨文 | SIL OFL-1.1 |
| **《说文》释义·反切** | shuowen.org | Apache-2.0 |
| **简繁映射** | OpenCC | Apache-2.0 |
| **中古音** | PHONO-ML Database（CRLAO/CNRS） | CC BY 4.0 |
| **上古音构拟** | Baxter & Sagart《Old Chinese》（2014） | CC BY 4.0 |
**连上古音构拟用的都是 Baxter & Sagart 那本权威著作，不是自己瞎标的。**⁠ ⁠**这份坦诚，比很多"看起来专业"的工具强太多。**
#### 几条必须说清的边界
**这个项目最可贵的地方，是作者在 README 里自己把局限全列出来了。我把关键的几条转给你：**
**第一，它是"昨天刚出生"的项目。**
**仓库 2026 年 10 月 13 日创建，截至现在约 55 Star——非常新。**⁠ 作者是⁠**一个人**⁠在做。⁠**数据可靠性可以放心，但它还在早期，别当成"成熟产品"来要求。**
**第二，"不编数据"是真的，但"查不到"也是真的。**
**甲骨文只覆盖 1,425 字，这是**⁠甲骨学界的客观上限⁠**（已释甲骨文约 1,600 字），换字体也突破不了；中古音覆盖 7,964 字、上古音只有 3,163 字——很多字点进去，那几栏就是横杠。**⁠ ⁠**这不是它偷懒，是数据本身就没有。**
**第三，《说文》原文本身是有错的，它选择"只标注不篡改"。**
**许慎写《说文》是在东汉，他没见过甲骨文，**⁠ 所以传统总结的"释形、释义、引例、分部、妄羼"五误，是真实存在的。⁠**这个项目怎么处理的？**⁠ ⁠**照实保留《说文》原文，再用"甲骨文实为 ××"做对照**⁠——因为"东汉人怎么理解这个字"，⁠**本身就是一种知识。**⁠ 我觉得这个态度很专业。
**第四，上古音、中古音都是"构拟"，不是"真读音"。**
**所谓上古音构拟，是用后世材料**⁠反推⁠**出来的拟音，**⁠学术上是"可能这么读"，不是"当年就这么念"。⁠⁠别拿它当"古人说话录音"来听。
**第五，谐声系列是自动归并的，个别字可能有误。**
**它根据《说文》里的"从 ×× 聲"自动归组，遇到释文异文，个别字的归属可能不准。**⁠ 严谨研究时，⁠**建议再核对原始出处。**
**第六，代码开源，但"数据"不看 MIT。**
**代码是 MIT 协议；但它收录的数据来自上面那一堆不同来源，各有各的授权（OFL、CC BY 等），再分发要保留声明。**⁠ ⁠**想拿它的数据去做二次开发，先看清楚来源授权。**
#### 写在最后
**这个项目让我觉得有意思的，不是技术多炫，而是它回答了一个我们从小就有、但从没被正经满足过的问题：**
**"我这个字，是怎么来的？"**
**它没有把这个问题的答案藏进学术专著里，而是做成一页网页——输入一个字，形、音、义、族全给你。**⁠ 甲骨文怎么写的、小篆长啥样、《说文》怎么说的、同族的字还有谁，⁠**一条时间轴串下来，越查越上瘾。**
**而且它做到了最难的一步：数据全都能溯源，"不知道"就老实写横杠。**⁠ 在一个什么都敢编的年代，⁠**"不编数据"四个字，本身就是一种稀缺品质。**
