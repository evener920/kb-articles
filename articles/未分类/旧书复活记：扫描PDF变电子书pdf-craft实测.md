先问你三个问题：书架上有没有那种**扫描版 PDF 电子书**？想复制一段文字，发现根本选不中？想在手机上读，结果一页要左右滑动八回？
再狠一点：手里有本外文扫描书，想读中文版——出版社没出过译本，怎么办？
这期的主角 **pdf-craft**，就是冲着这些痛点来的：把扫描版书籍 PDF「复活」成能编辑、能检索、能在阅读器里舒舒服服读的电子书，还能整本翻译、双语对照，甚至把译文「印」回原来的 PDF 版式里。老规矩，沙箱实测全记录。
先说清这事为什么难。扫描版 PDF 的每一页，本质是一张**图片**——文字在计算机眼里就是一堆像素点。普通工具只能 OCR 出散落的字，但一本书的灵魂在结构里：哪是章哪是节、脚注挂在哪句话下面、表格的行列怎么对、公式怎么排。结构丢了，OCR 出来就是一锅字粥。pdf-craft 的思路是**识别 + 结构重建**两手抓：OCR 负责「认字」，AI 模型负责「认版面」，最后按书的样子重排出来。
谁最需要它？做笔记要引用原文的读书人、想把绝版扫描书搬进 Kindle 的电子书党、拿着外文文献啃的科研人，还有想给家里老人把小字扫描书转成「能放大字体的 EPUB」的孝顺孩子——无障碍阅读这块，EPUB 比 PDF 友好太多。

pdf-craft 出自中文团队 oomol-lab，2025 年 2 月开源，现在 **6,593 星**，我查数据的当天作者还在提交代码——这是个活项目，不是论文配套代码。上过 GitHub Trending，协议 MIT。

它对自己的定位很克制：**面向扫描书籍、论文和技术文档的 Python 库**。转换时会识别正文、章节、目录、脚注、表格、公式和图片——也就是说，它不是简单 OCR 一堆散字，而是把「这本书的结构」也还原出来。
它对书做的三件事，一张图说清：

特别注意最后一行：**抽取结果可以复用**。识别是整条流程里最贵的环节，pdf-craft 把识别结果存成 .pcex 文件——先出英文原版，回头想出中文译本，直接复用抽取结果，不用再识别一遍。这个设计很懂「书是要反复折腾的」。

pdf-craft 准备了三条路，按自己的条件对号入座：

**路一：在线版**（pdfcraft.ai/pdf-craft/）。浏览器打开、上传 PDF、提交任务、下载结果。不用装 Python、不用配环境，注册登录即可用。官方明确说这是开源项目的官方在线服务，不是第三方套壳。
**路二：Python + 远程 OCR**。开发者的主流选择，OCR 跑在云端服务上（兼容 DeepSeek OCR 接口即可），本地不需要任何显卡。安装就两步：
# 需要 Python 3.11–3.13 + Poppler（页面渲染依赖）
python -m pip install pdf-craft
# Windows 用户再装个 Poppler 并加 PATH，见官方安装文档
装完之后，官方快速上手的完整代码长这样（照抄自官方 README，把 OCR 服务地址换成你自己的）：
from pdf_craft import DeepSeekOCRVendorConfig, PDFCraft, PDFOptions
# 三行配置：OCR 服务地址、密钥、模型名
craft = PDFCraft(pdf=PDFOptions(ocr=DeepSeekOCRVendorConfig(
 base_url="https://你的OCR服务/v1",
 api_key="你的密钥", model="deepseek-ocr")))
craft.convert_pdf_to_markdown("input.pdf", "output.md")
craft.convert_pdf_to_epub("input.pdf", "output.epub")
# 同步版 PDFCraft / 异步版 AsyncPDFCraft 两种姿势
没有 OCR 服务？两个选择：用路一在线版，或者走路三。
**路三：本地 OCR**。有 NVIDIA 显卡的重装选手专用：`pip install "pdf-craft[local]"`，配 CUDA 版 PyTorch，模型从 HuggingFace 拉取。识别完全在本机，数据不出门。
OCR 引擎目前有三个可选：**DeepSeek OCR、DeepSeek OCR 2、Unlimited OCR**（百度开源款），每个都支持本地/远程两种部署。识别引擎和翻译用的 LLM 是**两套独立配置**——认字用 OCR 专模，翻译用任意文本大模型，各司其职，这就是它能「识别一次、翻译多次」的底气。

写到最后给个明确结论：**只想转一两本书，直接上在线版**，注册个账号上传完事；**书多、想进自己的工作流，走 Python + 远程 OCR**这条路，一本书的成本就是 OCR 加翻译的 API 调用费；**隐私敏感或书不外传，本地 OCR** 一步到位。三条路都通向同一个结果：书架上那些「只能看不能用」的扫描 PDF，从此变成能搜、能引、能译、能装进口袋的活文档。
**▍避坑 FAQ**
**① Python 版本卡 3.11–3.13**：太新太旧都不行，装之前先看版本。
**② Poppler 是硬依赖**：Linux 用包管理器装 poppler-utils，Windows 要手动装并配 PATH，缺了它会报渲染错误。
**③ 在线版要登录**：上传免费，但提交任务需注册账号，按量充值制。
**④ 扫描质量决定上限**：官方自己都说效果取决于扫描质量、版面和 OCR 模型——大批量处理前先拿一册试水。
**⑤ 转出的 Markdown 带图片资源文件**：移动或分享时要连资源目录一起带走，别只拷 .md。
