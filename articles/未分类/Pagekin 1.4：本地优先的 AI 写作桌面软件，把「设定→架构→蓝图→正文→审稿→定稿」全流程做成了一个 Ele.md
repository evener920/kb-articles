# Pagekin 1.4：本地优先的 AI 写作桌面软件，把「设定→架构→蓝图→正文→审稿→定稿」全流程做成了一个 Electron App
> 💡 备注属性未写入，可能是备注属性名称或者类型被修改了，建议将字段类型设置为 rich_text，可以在小程序-操作-修改文章数据库页面进行调整

![](assets/416feb00ed72812e-1.jpg)
前几天在 GitHub 看到 `EthanYoQ/AI-Novel-Writer`（现名 **书童 Pagekin**），2.1k Star，标语是「开源免费的 AI 长篇小说写作桌面软件，为长篇小说和网文连载设计」。作为一个常用 Claude/ChatGPT 写小说、却总被「上下文窗口不够、角色设定跑偏、AI 味太重、版本管理混乱」折磨的人，正好拿来实测。
环境：macOS 15.6 (M4 Pro)、Node.js 22.14.0 (`nvm use 22`)、pnpm 11.11.0、Ollama 0.5.7 (本地跑 `qwen3:14b`)、Git 2.45。
```
# 1. 克隆仓库（浅克隆）
git clone --depth=1 https://github.com/EthanYoQ/AI-Novel-Writer.git
cd AI-Novel-Writer

# 2. 安装依赖（pnpm，指定版本）
pnpm install --frozen-lockfile
# 依赖树约 1.8 万包，耗时 ~60s（M4 Pro 32G）

# 3. 启动开发模式
pnpm dev
# Vite + Electron 启动，窗口弹出：书房界面、左侧书架、右侧欢迎页
# 无报错，热重载正常

# 4. 构建生产版（可选，验证打包流程）
pnpm build
# tsc 类型检查通过 + Vite 构建 + Electron Builder 打包
# 输出：dist-electron/ 含 Windows exe / macOS dmg (arm64/x64)
```
全程无报错。**关键体验**：项目把「开发、构建、打包、发布」全流程自动化了，GitHub Actions 云端构建三平台安装包，各自通过资格检查才进入同一个 Release。
**避坑点**：
- • **Node.js 必须 ≥22.14.0**（package.jsonengines 硬性约束），旧版本会在 tsc 或 vite build 阶段报错。
- • **pnpm 必须用仓库指定版本 11.11.0**（packageManager 字段锁死），别用 npm/yarn，否则依赖树会漂移。
- • **Windows 安装包未签名、macOS 仅 ad-hoc 签名未公证**，首次运行会被系统拦截，需手动允许（README 有详细步骤）。
- • **旧版便携 ZIP 无法自动更新**，必须手动安装一次正式安装包才能获得更新器。

#### 🔍 核心亮点
**1. 「书房→架构→蓝图→正文」：把「写长篇小说」的工业化流程做成了可视化流水线**
这是 Pagekin 最核心的设计——**不把「写小说」当成一次聊天，而是当成一个分阶段的工程项目**：
| 阶段 | 界面 | 核心动作 | AI 角色 | 人工确认点 |
| **书房** | 书架视图 | 新建/导入/管理作品 | 无 | 选作品、新建/导入 |
| **设定** | 表单页 | 填类型/受众/语言/总章数/章字数 | 可选生成建议 | 全部人工填/确认 |
| **架构** | 四分页 | 故事前提/角色名单/世界观/情节大纲 | 可逐节生成 | 四节逐个确认 |
| **角色** | 列表+详情 | 基础设定/当前状态/关系图谱 | 可生成/导入 | 逐个角色确认 |
| **蓝图** | 章节列表 | 逐章：目标/冲突/悬念/出场人物 | 分批生成/续写 | 逐章确认/修改 |
| **正文** | 单章视图 | 写稿→审稿→修稿→合并→定稿 | 逐步执行 | 每步逐段确认 |
**关键设计**：**每一章从「待写」到「定稿」都是一个原子流程**，AI 只负责起草，**每一步都要人工逐段确认**，不会出现「AI 一口气写完整本书、全是胡扯」的情况。
**实测**：我新建了一个「赛博朋克悬疑」项目，设定 50 章、每章 3000 字。
1. 1. **设定页**填完 → **架构页**让 AI 生成「故事前提」，稍微改了两句确认 → **角色名单**导入我预先写好的 5 个角色 JSON → **蓝图页**点「批量生成 1-10 章」，AI 分两批给出蓝图，我逐章微调 → **正文页**点「写第 1 章」，AI 基于蓝图+角色+世界观+前文摘要写出草稿 → 我点「审稿」AI 给出 8 条意见 → 我勾选 5 条、加 2 条自己的 → 点「修稿」AI 给出差异对比 → 我逐段选版本 → **定稿**。**全程零「跑偏」、零「失控」**。
**2. 「拆解仿写 + 续写 + 改写」三大核心技能：把「参考小说」变成「可复用的写作约束」**
这是 Pagekin 最差异化的功能——**不只是「让 AI 写」，而是「让 AI 学会怎么写」**：
| 技能 | 入口 | 核心流程 | 产出 |
| **拆解仿写** | 书房「小说拆解与仿写」→ 选「参考小说」 | 导入 .txt/.md/.epub → 按章拆解 → AI 提取结构/文风/章节蓝图 → 生成「仿写约束」 | 结构分析报告、文风指纹、章节蓝图模板、仿写约束（绑定到后续写作） |
| **导入原稿续写** | 书房「小说拆解与仿写」→ 选「我的原稿」 | 导入已写章节 → 按章节号识别 → 定稿入库 → AI 续写后续章节 | 已写章节入库、后续章节蓝图、续写上下文 |
| **段落续写** | 正文编辑器选中文字 → 点「续写」 | 选中段落 → AI 接着往下写 | 续写片段（可直接插入/放弃） |
| **整章改写** | 正文页「修稿」 | 写改写方向/勾选审稿意见 → AI 重写全章 → 差异对比逐段确认 | 新版本稿件（逐段可选） |
| **片段润色** | 正文选中文字 → 工具条 | 选「润色/扩写/改成对话」 | 修改片段 |
**实测**：我把《三体》前 3 章导入做「拆解仿写」，AI 给出了：「硬科幻悬疑结构、冷静理性文风、多视角切换、科学概念铺垫→悬念爆发的章节节奏」。把这个「仿写约束」绑定到我的新项目写稿阶段，**生成的草稿确实有了「三体味」：冷静叙述、科学铺垫、章末悬念**——这比单纯提示词「写得像三体」强得多。
**3. 「写作 Skill」插件系统：把「去 AI 味/文风/题材写法」做成可插拔的提示词包**
设置页「写作 Skills」支持三种导入方式：
- • 本机 Skill 文件夹 / 单个 SKILL.md
- • GitHub 上的 Skill 地址（如 https://github.com/xxx/writing-skills）
**导入流程**：软件先读取并展示 `SKILL.md` 内容 → 你检查无误 → 点「安装」 → 绑定到「规划/写稿/审稿/修稿」四个阶段的任意组合 → 之后该阶段的生成自动带上 Skill 提示词。
**关键限制**：**只支持自包含的提示词型 ****`SKILL.md`**，引用的 `references` 文本会一并装入。**脚本、hook、子代理、工具调用这类内容不会被安装，Skill 不能在你电脑上执行代码**——安全边界划得很清。
**实测**：我导入了一个「去 AI 味」Skill（来源：GitHub 某开源写作 Skill 仓库），绑定到「写稿」和「修稿」阶段。生成的草稿确实少了「综上所述、总而言之、在这个快节奏的时代」这类 AI 套话，句式更自然、口语化更强。**Skill 机制让「提示词工程」变成了可版本化、可分享、可审计的资产**。
**4. 模型生态：OpenAI 兼容 + Gemini 原生 + Ollama 本地，三条线全通**
| 协议 | 支持服务商 | 配置要点 |
| **OpenAI 兼容** | DeepSeek / SiliconFlow / 智谱 / OpenAI / xAI / NovelAI / 自定义 / **Ollama** | Base URL + Model + API Key |
| **Gemini 原生** | Google Gemini | Base URL + Model + API Key |
**Ollama 本地跑模型配置**（README 给得极详细）：
```
服务商： Ollama（本地）或自定义
协议： OpenAI 兼容
Base URL： http://127.0.0.1:11434/v1    # 注意是 /v1，不是 /api
API Key： 留空或填任意占位值
模型： 你的 Ollama 模型名，如 qwen3:14b
```
**知识库语义检索**另需向量模型，在「检索模型」里配置，也可用 `/v1` 地址。
**实测**：我配了 DeepSeek (云) + Ollama `qwen3:14b` (本地) 双模型，**写稿用 DeepSeek-V3（质量高）、审稿/修稿用本地 qwen3:14b（免费、隐私、够用）**，模型切换只需在下拉框选，**同一项目不同阶段用不同模型**，成本/质量/隐私三平衡。
**5. 「运行侧页」：把「AI 后台在干啥」透明化**
所有生成任务集中在右侧「运行侧页」三页签：
| 页签 | 功能 | 实测体验 |
| **进行中** | 实时流式输出、可取消、批量创作可暂停 | 写第 3 章时逐句出现、可随时点「取消」 |
| **历史** | 所有已完成任务记录、可查看输入/输出/耗时/Token | 翻看昨天的审稿记录、对比 Token 消耗 |
| **诊断** | 生成失败时的错误堆栈、已输出文本留作恢复候选 | 网络断了中断生成，已写 800 字留作恢复候选，一点「复制」接上 |
**批量创作**：一次最多连写 10 章，可暂停/继续，**生成失败时已输出文字留作恢复候选**，不会全丢。
#### 🚧 避坑与总结
**✅ 值得点赞的地方**
- • **全流程工业化**：设定→架构→蓝图→正文→审稿→修稿→定稿，每步有人工闸口，AI 不失控
- • **拆解仿写/续写/改写三大技能**：把「参考小说」变可复用约束、把「已写稿」变续写上下文、把「改写」变差异对比逐段确认
- • **Skill 插件系统**：提示词工程资产化、可版本化、可分享、安全边界清晰（只能提示词、不能跑代码）
- • **模型生态全**：OpenAI 兼容 + Gemini 原生 + Ollama 本地，双协议、多预设、自定义全支持
- • **本地优先、隐私优先**：作品/配置/Key 全在本地 SQLite + 文件夹，云端只发提示词上下文
- • **版本历史/导出备份/WebDAV 同步**：每章历次稿件全留存、可对比可回退、导出 MD/TXT、WebDAV 备份
- • **GPL-3.0 开源、Electron + React 19 + Codemirror 6 + SQLite**：技术栈现代、代码可审计
**⚠️ 踩坑提醒**
- • **不带模型、必须自备 API Key 或 Ollama**，零配置开箱即用做不到
- • **v1.3.0 界面大改版，助手聊天入口暂时隐藏**，习惯用聊天辅助写作的需适应
- • **Windows 安装包未签名、macOS 仅 ad-hoc 签名未公证**，首次运行需手动允许
- • **不保证任意第三方 API 兼容**，Anthropic/Azure/KoboldAI 原生接口需单独适配器
- • **不替代作者创意/事实核查/版权判断**，AI 写的内容必须人工审阅
- • **不提供在线发布/阅读社区/云端模型账号**，纯本地生产工具
- • **Windows 便携 ZIP 无法自动更新**，需手动装一次正式安装包
