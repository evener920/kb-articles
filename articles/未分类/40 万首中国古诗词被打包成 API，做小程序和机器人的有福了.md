# 40 万首中国古诗词被打包成 API，做小程序和机器人的有福了

> 💡 原文链接:[https://mp.weixin.qq.com/s?__biz=MzkxNjY3OTg1Ng==&mid=2247484461&idx=1&sn=fd38879e4d4f2374b1b52a8c163b8a6f&chksm=c00317d01b48311f11585afd9a7e219c9ea846eb56df238d00b8ba76325ce88dca37570803d3#rd](https://mp.weixin.qq.com/s?__biz=MzkxNjY3OTg1Ng%3D%3D&mid=2247484461&idx=1&sn=fd38879e4d4f2374b1b52a8c163b8a6f&chksm=c00317d01b48311f11585afd9a7e219c9ea846eb56df238d00b8ba76325ce88dca37570803d3#rd)
想要做个每日古诗壁纸、墨水屏时钟、飞花令群机器人，或者古诗词背诵小程序，很多人第一步都会被“搞数据”劝退。
去网上找诗词数据，要么排版稀烂、朝代混杂，要么繁简夹杂甚至满地错别字。自己写爬虫抓网页、洗文本、建数据库，往往正经功能还没动笔，两天时间全搭在洗数据上了。
刚在 GitHub 上蹲到了一个叫 **chinese-poetry-api**（诗泉）的开源项目。作者直接把将近 **40 万首中华古诗词**，打包成了一套开箱即用的高性能 API 服务。
不用爬虫、不用建库，一个 Docker 命令拉起来，或者直接调在线接口，诗词、作者、朝代、体裁全到手了。
![](assets/40 万首中国古诗词被打包成 API，做小程序和机器人的有福了-1.jpg)
---
#### 一、 它肚子里装了多少东西？
很多人以为这只是把课本里几百首古诗凑在一起的玩具，其实它的底层基于 GitHub 著名的中华古诗词开源库，并且专门跑了一遍错字和作者朝代修正。
直接调用它的统计接口，能看到这组沉甸甸的数据：
- • **总收录诗词**：**371,313 首**（近 40 万首）
- • **涉及作者**：**13,577 位**
- • **跨越朝代**：**11 个**
- • **诗词体裁**：**17 种**
从《诗经》、《楚辞》、先秦汉赋，到唐诗、宋词、元曲应有尽有。光是七言绝句和七言律诗就收录了 15 万首，宋词与五代词超过 2.1 万首。
每首诗都规整地打上了作者、朝代和体裁标签，字段结构很规范，拿来就能直接渲染到前端。
---
#### 二、 接口调起来有多省事？
项目同时支持 REST 和 GraphQL 两种接口，这里挑几个最常用的实战场景看看：
**1. 随机来一首（适合日历、墨水屏、每日一签）**
做每日诗词卡片或者墨水屏桌面摆件，最核心的需求就是每天或每次刷新“随机来一首”。
直接发个 GET 请求：
```
curl "http://localhost:1279/api/v1/poems/random"
```
几毫秒内就能拿到一个干净的 JSON：
```
{
  "id": 309946,
  "title": "静夜思",
  "author": { "name": "李白" },
  "dynasty": { "name": "唐" },
  "type": { "name": "五言绝句" },
  "content": [
    "床前看月光，疑是地上霜。",
    "举头望山月，低头思故乡。"
  ]
}
```
还能组合过滤条件，比如只要李白的绝句，或者只要宋代的词：
```
curl "http://localhost:1279/api/v1/poems/random?author=李白&type=五言绝句"
```
**2. 飞花令与全文搜索（适合诗词对战、聊天机器人）**
要做微信群里的飞花令机器人，或者带搜索框的小程序，可以用它内置的搜索接口：
```
# 飞花令按字随机出诗（比如带“春”字的诗）
curl "http://localhost:1279/api/v1/poems/random?char=春"

# 按标题搜索
curl "http://localhost:1279/api/v1/poems/search?q=静夜思&type=title"

# 全文内容检索
curl "http://localhost:1279/api/v1/poems/search?q=明月"
```
**3. 简繁体一键切换**
很多古诗应用要面向海外或港澳台用户，通常得自己在后端挂一个 OpenCC 做简繁转换。
这个项目在数据库层面就做好了双语索引，所有接口直接带上 `lang` 参数即可：
```
curl "http://localhost:1279/api/v1/poems/random?lang=zh-Hant"
```
底层转换由 Go 语言实现，官方压测转换耗时约 **300ns/op**，对请求延迟几乎毫无影响。
---
#### 三、 部署极其轻量，17MB 镜像开箱即用
很多开源数据项目动不动就要跑 Python 环境、挂载几十 G 的数据库镜像，小服务器直接爆内存。
这个项目是用 Go 编写的，编译完的 Docker 镜像仅仅只有 **17.2 MB**。
哪怕用的是几十块钱一年的 1 核 1G 基础云服务器，或者家里的软路由、树莓派、群晖 NAS，都能轻松无感常驻运行。
部署只需要一行命令：
```
docker run -d -p 1279:1279 palemoky/chinese-poetry-api:latest
```
服务默认跑在 1279 端口，内部自带 IP 访问限流，直接暴露在公网也不用担心被恶意脚本刷死。
如果手头暂时没有服务器，作者还部署了一个公网在线调试版本，打开 `https://poetry.palemoky.com` 就能在网页上直接点选调试各个接口。
---
#### 四、 适合拿来做什么？
手头有这几个场景的朋友，直接调这个接口能省下一大半开发时间：
- • **墨水屏与硬件摆件**：ESP32、树莓派做个桌面古诗词日历，定时调一次随机接口，不用在单片机脆弱的存储里塞离线大字库。
- • **小程序与独立工具站**：做诗词打卡、字词接龙、古风排版壁纸，不用管后端数据维护，一两个晚上就能把前端交互搓出来。
- • **微信/企微群机器人**：在群里接入飞花令问答、早安诗词推送，几十毫秒的响应速度完全不会让人感到卡顿。
- • **大模型 Agent 知识外挂**：大模型背古诗经常“张冠李戴”、杜撰诗句。把它作为本地检索工具（Tool Calling）喂给 Agent，诗词问答就能做到 100% 准确。
