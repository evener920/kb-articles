# TVBox 有电脑版了，装完就有片源

家里有电视盒子的，多半装过 TVBox。填一条订阅地址，几十个影视站一起搜，还能看直播。好用，但它的活动范围基本锁在客厅里。
想在电脑上用，过去只有两条路：装安卓模拟器，或者去网页版凑合。模拟器重、卡、没快捷键；网页版找片全靠手点，复制地址再粘进播放器，来回折腾。
上个月 GitHub 上有个项目把这件事往前推了一步。hgtuj5688/tvbox-desktop，九月底开源，一个多月涨到接近八百星，MIT 协议。作者的项目自述只有一句话：纯白极简的 Windows 影视聚合客户端。我装着用了一阵，说说真实感受。
### 一、它是个壳，作者也不装
先把最容易误会的地方说清楚：它不含任何影视内容。
装完你能看到东西，是因为首次启动时它自动装了一份内置订阅，五个实测存活的公开采集接口，加一条公开直播源、五条首页内容位，然后立刻同步一次。等首页出现五排海报，就说明通了。
这份内置源是“上手能跑”，不是长期饭票。想用自己的，进设置里的配置源，把手里那条 TVBox 订阅地址原样贴进去，A、B 两种方言都认。删掉内置源它也不会自己冒回来，程序在 data\bundled-sources.json 里记了账，只在一台从没装过的机器上自动装一次。
技术栈是 Electron 44 + React 19 + TypeScript + Vite 7，播放内核 ArtPlayer 加 hls.js。它不是把手机 App 放大到显示器，侧边栏七个入口，首页五排横滑海报，基本是照着键盘鼠标重写了一遍。字体、间距、留白都克制，没有那种满屏“VIP 破解”“4K 蓝光”的排版。
### 二、搜片：一次打五个站，同名自动合并
顶部搜索框输片名回车，它并发去打所有可用站点，结果一条条流式推回来，不用等全部跑完。
两个细节比同类细。不同站的同一部剧合成一张卡，卡上标“3 个源”，鼠标悬停能看是哪几个站；同一个站对同一部剧常返回好几条，不同清晰度、方言版混在一起，它每站只留信息量最大的一条，所以卡片不会顶着“庆余年第二季粤语”这种奇怪后缀。别名剥离也聪明：带括号的《庆余年之大凉太子爷》会和不带括号的合并，但括号里是“第61-81集”“特别篇”这类分季分集信息时会保留，免得第一季第二季搅一块。
搜索页有个“过滤解说”开关，默认开着，把“XX解说”“一口气看完”这类二创剔掉。分类页会把各站的分类树按祖先链归并，最后合成电影、电视剧、动漫、综艺、纪录片、短剧几个大类，滚到底自动翻页。
### 三、换源那个祖传坑，它替你踩了
这条是我觉得最值的地方。
采集站有个老毛病：第一条线路经常不是 m3u8，而是网页分享页。别的播放器把这个地址直接丢进内核，结果就是黑屏，你还以为是源挂了。TVBox Desktop 的处理分三步。本来就是直链的，直接放；是网页地址，先自己读一遍那个页面，DPlayer 的壳十有八九把地址明文写在 const vid 里，抓出来就完事，实测一两秒；还读不出来，才按战绩去轮询解析接口，失败的往下沉。
换的时候播放器上盖一层“正在换播放地址…”，换完会写明是靠哪条路换出来的、花了多久。换不出来它也不装成功：每一条为什么失败都写在上面，而不是转圈转到你怀疑人生。
这个价值比界面好看重要得多。以前找片是开浏览器、切几个站、复制链接、粘进播放器、黑屏、再换一条，现在这几步被默认行为吃掉了。
### 四、直播：不堆源，把手上线路用起来
m3u 和 txt 两套语法都能吃，同名频道合并成一张卡，卡上多条线路。虎牙抖音那种带防盗链签名的地址，它只存房间号，比如 huya://10188，点开时才去换真地址，不怕过期。
公开直播源的问题不是少，是死。作者实测那批源里约 27% 的地址拉不起来，32% 的频道一条能播的线路都没有。所以它的思路不是继续加源，而是把手上这些用起来：进分组就在后台预热前 60 条，每次最多 8 条并发，只读 4KB 判活，成功缓存半小时、失败只留五分钟；点开优先用探到的活线路，播放中途断了自动切下一条；整组全死链的频道默认藏起来。
内置测试分组是 14 个分组、541 个频道。频道总数不等于能播数量，这点别误会。
### 五、外挂播放器，连你装哪它都找得到
内嵌的 ArtPlayer 日常够用。碰上浏览器内核放不了的格式，比如某些 mkv，点“外部播放器”就唤起 PotPlayer、mpv、VLC。
设置页里有个“检测本机播放器”，扫常见安装路径、扫 PATH，还会去问注册表里 .mkv、.mp4、.ts、.flv 的默认打开方式，装在 D:\某处\ 的绿色版播放器就是这么被捞出来的。检测结果每条带一个“用这个”，点一下就填好路径。参数模板里 {url} 是播放地址、{title} 是片名，想全屏启动就填 --fullscreen {url}。
### 六、AI 剧情总结：有比没有好
播放页下面有个 AI 总结区，点了才发请求，Key 只存本机的 data/settings.json，只在主进程里用。两种模式，看一遍再总结，每 20 秒抽一帧，一集七十来帧丢给多模态模型，成本约两分钱；或者只看资料，纯文本推断。
Key 得自己准备，用 DeepSeek 官方的可以，用中转站也行，我自己挂了一个在 nbkiter.xyz，按量计费，一集两分钱这个量级，充几块钱能用很久。提这个是顺带，它确实得有一把 Key 才亮。
作者自己写得很坦白：抽帧没有音轨，带硬字幕的片读得准，不带字幕的只能描述画面，而且抽帧会把整集缓冲一遍。所以它适合“手边没字幕，又想知道这集大概讲了什么”，不适合当剧情考据。这个功能我没有重度用，两分钱一集倒是不心疼。
### 七、安装：两个包，两个坑
去 GitHub Releases 拿，只有两个文件。TVBox.Desktop-0.1.0-x64.exe，约 115 MB，安装版，推荐；TVBox.Desktop-0.1.0-x64.zip，约 158 MB，免安装，解压即用。
坑一，它没买代码签名证书，首次运行 Windows SmartScreen 会拦一下，“Windows 已保护你的电脑”，点更多信息再点仍要运行。这不是病毒告警，是没证书。
坑二，别装进 C:\Program Files。程序是便携形态，配置、收藏、历史全写在程序同级的 data\ 目录里，装到需要管理员权限的地方会写不进去，配置退回系统用户目录。能用，但便携性没了。
顺手记一下 data\ 里有什么：settings.json 是设置，sources.json 是配置源，sites.json 是站点本地覆盖，parses.json 是手动加的解析接口，session\ 是缓存。卸载时这个目录一起删，收藏和历史全没，想留就先整个复制出来。反过来这也是好处，换电脑把整个程序目录拷走，配置跟着走。
### 八、短板先说，免得你装完骂人
安卓那套要 jar/dex 的 spider，也就是 type 0 站点，桌面端跑不了，界面上会灰显并写明原因。订阅里要是大量 type 0，这里基本用不上，这对重度 TVBox 用户是硬伤。
只有 Windows x64，没有 macOS、没有 Linux，也没有 ARM 版。
首页内容位比较简单，每行按“最近更新”或指定分类拉一页，最多 24 条，没有“换一批”。
项目很新，2026 年 9 月底首发，版本还停在 0.1.0，单人维护，后续节奏不好说。作者倒是认真，自检脚本跑了 177 项端到端断言，CHANGELOG 里连“翻页后列表重排”“进度条被 0/0 覆盖”这种细活都逐条记了怎么修。但认真不等于能长期维护，别把它当基础设施。
公开源随时失效，这是采集站的生命周期，不是软件的问题。
· · ·
我一直觉得这类工具真正解决的不是“能不能看”，是“找片的摩擦”。电视盒子那套生态最成熟，可它长在客厅；网页聚合站什么都能搜，但要你手动搬运。TVBox Desktop 把同一份订阅搬到了电脑前，顺手把换源、挑线路、认播放器这些以前要试好几遍的活儿变成了默认行为。
客厅躺沙发上用盒子，坐在电脑前用它，订阅还是同一份 JSON。这种两条腿走路的分工，对我来说够了。
最后还是那句：它只是个壳，内容来自你自己添加的订阅。看片走官方渠道最省心，别传播来路不明的源，也别拿来商用。
