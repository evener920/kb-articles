## 给 macOS 补上长截图：PinboardShot 的原生采集与浏览器方案
在 Mac 上截一张图很容易。要把一篇长文档完整留下来，圈出其中两处问题，再把它贴在旁边对照修改，事情就开始变得零碎。
![](assets/给 macOS 补上长截图：PinboardShot 的原生采集与浏览器方案-1.png)
系统截图能拿到眼前的画面，屏幕下面的内容还需要继续滚动。浏览器插件能处理网页，截完以后，标注、复制、贴屏又可能回到另一个工具。只是想保存一页内容，也可能先碰到付费版、账号，或必须安装桌面 App 的前置条件。
做 PinboardShot 时，我们想接住的就是这段过程：从看见内容，到截下来，再到继续使用它。长截图是其中最难收稳的一环，尤其是在 macOS 的不同窗口和浏览器页面之间。
后面逐渐形成了两条采集路径：普通应用保留原生滚动截图，Chrome 网页交给插件读取实际滚动位置。插件能连接 Mac App，也能独立保存 PNG。两条路径共享同一个目标——把已经确认截到的内容交给用户，并说清楚什么时候只能得到一部分。
**本文以当前仓库代码和浏览器扩展 0.3.0 的实现为依据。源码、本地构建与商店版本可能不同，文中的独立保存等能力需要对应版本；不把本地已实现等同于商店已经更新。竞品价格核对日期为 2026 年 10 月 6 日，单位为美元，税费与后续调整以官方页面为准。**
### 01 / macOS 的痛点，延伸到了截图之后
Apple 的截图说明覆盖全屏、窗口和选区；系统截图工具没有提供一个通用的滚动长截图入口。对于只需要一屏内容的人，这些快捷键已经很好用。需要留下长文档或长对话时，仍然要找其他办法。
打印成 PDF 适合保存文档，但页面可能应用打印样式，交互区域也未必进入输出。分几张截图再拼起来可以保留画面，却需要手动检查重叠、重复和缺口。浏览器整页截图又只覆盖浏览器这一部分工作。
开发和设计场景里，拿到图片以后还有下一步：圈出间距问题，遮住敏感文字，把设计图贴在目标窗口旁边，或者把两次截图放在一起比较。每次都先存文件、切到编辑器、处理完再重新打开，成本很小，却会反复发生。
因此 PinboardShot 的 Mac 端先围绕这条路径组织功能：区域、窗口或屏幕采集后，可以继续标注、复制、保存和贴屏。贴图能保持在其他窗口上方，调整大小、透明度或鼠标穿透，也能进行并排和差异对比。需要回头查找时，截图历史和本地 OCR 索引提供另一条入口。
长图进入这条路径以后，也有实际用途：删除不需要的中段，按页高切成连续 PNG，或导出 PDF。我们没有要求用户拿到一张很高的图片后，再去寻找长图编辑工具。这些能力的实现与范围可以在项目说明中查看。
### 02 / 市面上有成熟工具，收费也需要拆开看
做这个功能之前，先看已有产品是必要的。长截图、标注和贴屏都已经有成熟实现，把它们笼统写成“别人做不到”，没有事实依据。
收费同样不能只看一个购买按钮。下面三款产品代表了不同的使用路径：

| CleanShot X | Mac 截图工具，提供滚动截图、标注、贴图等能力。 | Basic 为 $35，一次购买可继续使用，含一年更新；后续更新可选 $19/年。Pro 按年付费时为 $10/用户/月，增加云和团队能力。 |
| Shottr | Mac 截图工具，提供滚动截图与标注；有免费使用路径。 | 免费使用满 30 天后出现升级提醒。Basic 为 $12 一次性购买，商业使用需要许可；Friends Club 为 $30。 |
| GoFullPage | 浏览器整页截图；基础截图和导出图片、PDF 免费。 | 裁剪、编辑与标注工具属于 Premium，$12/年；下载未编辑的基础截图不需要订阅。 |
对应依据是 CleanShot 的功能页与价格页、Shottr 的购买页与免费使用说明，以及 GoFullPage 的官方 FAQ。
如果需求只是免费保存一张长网页，GoFullPage 已经能满足很多情况；Shottr 也提供了免费使用的选择。CleanShot 的本地 App 则有一次购买的方案，不能把它写成必须持续订阅才能截图。
付费工具的问题主要是是否符合自己的使用频率和工作流。偶尔截一次长图的人，可能不想购买一套完整工具；需要反复标注和贴屏的人，又可能愿意为成熟体验付费。云存储和团队管理有它们的价值，对只想把图片保存在本机的人，则未必是必要能力。
我们选择继续做 PinboardShot，是因为希望免费提供这一条本机工作流，并用 MIT 许可公开实现，方便检查和修改。免费开源可以降低采用门槛，是否顺手、采集是否可靠，仍然要靠实际使用来判断。
### 03 / 普通应用：先确认画面接得上，再追加像素
原生滚动截图面对的是窗口画面。工具能获取一帧图片，却通常拿不到应用内部那个文档的可靠滚动坐标。发出一个滚动事件，也不代表正文一定移动了对应距离：应用可能还在渲染，滚动可能被其他区域接住，画面里也可能有固定栏和动画。
PinboardShot 用 ScreenCaptureKit 采集目标窗口，在选定的正文区域内比较相邻画面。匹配先缩小位移候选，再细化到原图行位置；只有足够可信的重叠，才把后面新增的原始像素追加到长图中。重复画面不继续增长，有多个相近候选或无法定位时，采集会暂停追加。
这会让工具在某些页面上显得保守。连续重复的表格行、几乎空白的区域，或正在改变的内容，都可能让两段画面看起来同样合理。我们更愿意把这种不确定性显示出来，让用户减速、回滚到已有预览对应的位置，再继续采集。
自动滚动也遵循同一个约束。下一步滚动要等到新画面确认稳定；只等一个固定时间，然后不断发送滚动事件，容易让采集追不上正文。当前自动滚动会观察帧的变化与追加结果，失配、停滞或目标变化时暂停；手动滚动仍然保留，用户可以在预览里检查内容是否接上。
实现分别位于 ScrollCaptureStitcher.swift 和 ScrollCaptureAutoScroll.swift。较长的内容采用分段和临时文件支撑采集，预览另行缩小；生成与导出仍会受到内存、磁盘和图像编码能力的限制，不能据此承诺无限长度。
这条路径让网页之外的窗口也有机会进入同一个编辑流程。它仍然依赖目标应用的实际渲染与滚动行为，需要 macOS 屏幕录制权限；自动驱动滚动还需要辅助功能权限。兼容性不会因为按钮上写了“自动”就消失。
### 04 / Chrome 网页：让浏览器提供滚动位置
网页给了我们另一种条件。插件可以知道页面滚到了哪里、视口有多大、正文有多高，还可以检查某些元素是否固定在屏幕上。因此我们为 Chrome 增加了专门的采集路径。
它仍然截取浏览器真实渲染出的 PNG 画面，没有把 HTML 重新绘制成另一张图片。区别在于，分段的位置由网页实际滚动坐标确定：滚动一段，等待位置与可见资源稳定，截取视口，再把图片和对应坐标交给合成端。
Chrome 的 `captureVisibleTab` 提供的是可见区域截图，也有调用频率限制。当前实现让采集至少间隔 650 毫秒，并在截取前后检查页面位置与视口尺寸。用户切换目标窗口的标签页、页面不再按预期滚动，或视口发生变化时，会明确停止这次采集。
Retina 是这里容易出错的一层。网页报告的宽度是 CSS 像素，PNG 的宽度是图像像素。例如视口宽 900，图片宽 1800，坐标就需要按实际比例换算。独立合成器从 PNG 尺寸计算比例，并校验后续分段的一致性；不能只把网页里的高度直接当作输出图片高度。
固定元素也需要分别处理。`position: sticky` 的章节标题可能在首屏以下才出现，把它们全部隐藏会漏内容；当前实现临时让它们回到正常文档流。`position: fixed` 的元素在首段保留，后续隐藏，再根据底部遮挡调整重叠。截图结束后恢复原来的内联样式、滚动行为和位置。
还有一类页面，外层文档根本不滚动，只有中间的正文面板在滚。插件目前会在外层不滚动时，识别单个主要、完整可见的内部滚动区域，并按真实像素比例裁切，只输出这一块内容。多个主要区域、被裁切或带缩放变换的面板会被拒绝，避免把外围空壳当成完整正文。
我们因此减少了浏览器场景里依靠图像相似度猜位移的工作。但页面坐标也有边界：虚拟化列表会移除屏幕外的节点，懒加载会改变高度，动画会持续改变像素。坐标正确，只能说明图片摆放位置有依据，不能证明网站的全部数据都被加载出来了。
### 05 / 一个插件，连接 App 与独立保存两条出口
最初的浏览器路径，是插件采集、Mac App 合成，再打开现有标注编辑窗口。对已经使用 PinboardShot 的人，这能直接接上复制、贴屏和长图处理。
本机连接采用 Chrome 的 Native Messaging。插件把分段图片送给本机宿主，宿主验证会话、顺序、坐标与图像尺寸，App 再读取受控的完成结果。注册限制到固定插件身份，传输按长度分块；通道没有使用截图上传服务。
后来我们又补上一个更直接的需求：只安装了浏览器插件，也应该能截长图。没有检测到 App 时，面板不该只剩下一个连接失败提示。
于是 0.3.0 增加了独立模式。开始前的握手无法建立兼容连接时，插件在浏览器内用 OffscreenCanvas 按坐标拼接 PNG，结束后交给 Chrome 下载。用户可以使用浏览器配置的下载位置，也可以勾选“保存时选择位置”，打开保存对话框。不需要先安装 Mac App，也不需要注册账号。
保存目标在开始时选定。已经进入 App 模式以后，如果本机连接中途断开，就报告这次失败；不会临时改道下载另一份文件。这样用户能知道结果应当出现在哪里，也避免一个未确认的任务产生两套输出。
“保存成功”也要等到文件真正写完。拿到 Chrome 的下载 ID 只说明下载请求建立了；实现会确认自己的下载完成或中断。页面在保存对话框出现前恢复，取消保存会释放内存中的结果，保存等待有两分钟期限。下载权限只用于本插件产生的 PNG 及其状态，不处理其他下载。
独立模式目前把单边限制在 32,767 个物理像素，总像素限制在 3,200 万。四字节像素下，3,200 万像素仅底层缓冲就约 128 MB；画布增长和 PNG 编码还会有额外开销。超过预算会明确报错，不会悄悄缩小或截掉后半段，再把它称为完整截图。连接 App 能换一条处理路径，也仍然有自己的采集与资源边界。
### 06 / 停止、取消和进度，决定用户能否放心操作
把采集链路接通以后，我们又花了一轮时间打磨插件面板。界面最后采用橘色方向，换了页面采集图标，采集时增加扫描和进度动效；暂停时动画停止，系统启用减弱动态效果时也会减少动画。
更影响使用的是操作语义。“停止”表示结束继续采集，并保存已经截到的部分；“取消”表示放弃这次未完成结果。两个按钮都让滚动停下来，却不能交付同样的文件。
同样，点了暂停按钮，不等于任务已经暂停。控件需要等待采集状态确认，期间显示反馈并阻止重复请求。如果转换没有得到确认，就告诉用户操作尚未确认，不能在界面上先假装完成。
进度条只描述正在执行或收尾的任务。完成、停止、取消和错误以后，面板清空进度条与百分比，改为显示独立的结果信息。重新打开面板或切换语言，也不应该把上一次的进度重新摆出来。
这几个细节把工具的行为变得可预测：暂停后能继续，停止后得到部分结果，取消后丢弃未完成结果，保存失败时明确需要重试。界面上的动效帮助辨认状态，操作结果才是用户真正需要相信的东西。
### 07 / 优势成立在哪里，边界又在哪里
对需要在 Mac 上反复使用截图的人，PinboardShot 把采集、标注、复制、贴屏和长图处理接在一起。对只需要网页 PNG 的人，独立模式保留更短的路径。源码开放、本机处理，以及无需付费解锁这条截图流程，是我们当前提供的选择。
插件使用 Manifest V3 和 `activeTab`，在用户主动发起后取得当前页面的临时访问权限，没有常驻的全网站 host 权限。Chrome 的权限说明解释了这种授权方式。采集本身仍然会读取和处理当前页面内容，本机处理并不等于没有数据访问。
默认截图与这条浏览器采集路径不把图片上传到 PinboardShot 服务器。App 检查更新需要网络；如果用户主动配置并使用远程 OCR 插件，框选区域会发送到指定服务。这些是不同的操作，不能把整个 App 的所有使用方式概括成“永远不联网”。
目前 Mac App 要求 macOS 14 或更新版本，Chrome 插件要求 Chrome 116 或更新版本。浏览器采集针对普通 HTTP/HTTPS 页面；受保护页面、iframe 或 Shadow DOM 内部滚动、虚拟化列表和持续动画没有完整性保证。Safari、Firefox 也没有接入这套插件与本机通道。
测试的结论同样需要有范围。这次整理文章时，独立合成与下载模块的 17 项自动测试通过，覆盖分段重叠、坐标缺口、图像尺寸、预算、保存中断和取消等条件。仓库还提供合成网页的真实渲染测试，用于验证内部面板裁切、粘性标题、固定页脚与页面恢复。它们能检查具体机制，不构成对所有网站的兼容性承诺。
实际采用时，可以先看官网与源码仓库。浏览器安装和本机连接见插件说明。本地开发通过 Chrome 的“加载已解压的扩展程序”验证 `browser-extension/`；使用公开仓库时，需要先核对其版本是否已包含本文对应的变更。商店更新有独立的审核节奏，普通安装以当前版本实际提供的能力为准。
做完这几轮，我更明确了长截图里值得坚持的一件事：让内容、位置和完成状态各自有依据。普通窗口确认画面重叠，网页确认实际坐标，保存确认文件结果。用户只想留下一页内容，工具应该替他接住这些细节，并在接不住时把边界说清楚。
